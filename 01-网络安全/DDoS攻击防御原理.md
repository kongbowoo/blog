# DDoS 攻击防御原理

> 概述：DDoS（Distributed Denial of Service，分布式拒绝服务）攻击通过控制大量僵尸主机或反射节点，向目标发送超出其处理能力的流量或请求，耗尽网络带宽、连接资源或计算资源，导致正常用户无法访问服务。本文整理常见 DDoS 攻击类型的原理与防御思路。

## HTTP 慢速连接攻击

### 攻击原理

HTTP 协议在收到完整请求前需要保持连接。慢速连接攻击利用这一特性，以极低速率发送或接收数据，长时间占用服务器的连接资源：

- **Slowloris**：发送不完整的 HTTP 请求头（每 10~15 秒补发一个 `X-a: b` 字段），让服务器一直等待剩余头部，连接被持续占用。
- **Slow POST / R-U-Dead-Yet**：在请求头中声明一个很大的 `Content-Length`，随后以极慢速率（如每 10 秒 1 字节）发送请求体，占用连接。
- **Slow Read**：正常发送完整请求，但以极小的 TCP 窗口（如每次只读 1 字节）缓慢读取响应，迫使服务器保持连接并占用发送缓冲区。

此类攻击仅需低带宽和少量机器即可生效，属于典型的"低慢速"（Low and Slow）应用层攻击。

### 攻击特征

- 单个连接持续时间异常长（远超正常请求）。
- 请求头/请求体到齐时间间隔规律且缓慢。
- HTTP 并发连接数攀升，但请求数与流量占比极低。

### 防御思路

- 设置请求超时时间（Header/Body 超时），超时未收到完整请求即断开连接。
- 限制单 IP 最大并发连接数与最大请求时长。
- 使用支持异步非阻塞 I/O 或具有抗慢速攻击能力的服务器（如 Nginx 事件模型），避免连接占满 Worker。
- 通过反向代理/WAF 前置清洗，识别慢速行为特征并封禁。

## DNS 放大反射攻击

### 攻击原理

DNS 放大反射攻击是典型的带宽耗尽型 DDoS，利用开放递归解析器（Open Resolver）实现流量放大：

1. 攻击者伪造源 IP 为受害者的 IP，向大量开放的 DNS 递归服务器发送查询请求。
2. 查询内容选择响应体积远大于请求体积的类型，如对任意域名发送 `ANY` 查询（尤其针对配置了 DNSSEC 的域名，响应可达请求的 50 倍以上）。
3. DNS 服务器将大体积响应"反射"回受害者，攻击流量经过放大且难以溯源。

放大倍数参考：`ANY` 查询约 28~54 倍，DNSSEC 签名域名响应更大。

### 攻击特征

- 受害者收到大量来自公网 DNS 服务器（53 端口）的 UDP 响应报文。
- 上行请求量远小于下行响应量，响应内容与受害者的实际业务无关。
- 源 IP 分布零散，均为全球各类 DNS 服务器。

### 防御思路

- **治理源头**：管理员应关闭自身 DNS 服务器的递归查询对外开放（仅对可信网段提供递归），或使用 RRL（Response Rate Limiting）限制响应频率。
- **网络侧过滤**：运营商部署 BCP 38（uRPF）对伪造源 IP 的报文进行过滤，从源头阻断反射。
- **受害侧防御**：与 ISP 协作进行流量清洗、黑洞路由；对 UDP 53 来源流量做限速或异常检测。

## DNS 缓存投毒攻击

### 攻击原理

DNS 缓存投毒（Cache Poisoning）通过向 DNS 递归服务器的缓存中注入伪造的域名解析记录，将用户引导至攻击者控制的站点：

1. 用户/递归服务器向权威服务器发起域名查询（UDP，无连接、无认证）。
2. 攻击者抢在权威服务器响应之前，向递归服务器伪造应答报文。
3. 伪造报文需匹配查询的源端口、随机 Transaction ID（16 位）等字段，匹配成功即被接受并缓存。
4. 缓存期间（TTL 有效期内），所有访问该域名的用户都被解析到伪造的 IP。

Kaminsky 攻击是该类攻击的著名变体：每次查询随机化的子域名（如 `abc123.example.com`），大量伪造 NS 记录响应，即使单次伪造失败也能持续重试而无需等待缓存过期。

### 危害

- 将银行、电商等站点流量劫持至钓鱼页面，窃取账号密码。
- 结合 DDoS：先将某权威域名解析劫持到黑洞地址，使依赖该域名的服务不可用。

### 防御思路

- **部署 DNSSEC**：对 DNS 响应进行数字签名验证，从根本上解决伪造应答问题（同时注意 DNSSEC 大报文可能被用于放大攻击，需配合 RRL）。
- 递归服务器启用源端口随机化、Transaction ID 随机化，增大伪造难度。
- 限制递归服务器的出站查询路径，关闭不必要的 `ANY` 响应。
- 关键业务域名的 NS/TTL 配置规范化，缩短被投毒后的影响窗口。

## HTTP GET 攻击

### 攻击原理

HTTP GET 攻击是应用层（L7）DDoS 的常见形式：攻击者（或被控的傀儡机、HTTP 代理）模拟正常浏览器行为，高频向目标发送 GET 请求，请求看似合法但会触发服务器最昂贵的处理逻辑：

- 反复请求需要大量数据库查询、文件 I/O 或动态渲染的页面（如搜索、报表接口）。
- 请求中携带变化的 URL 参数（随机 query string），绕过静态页面缓存。
- 耗尽服务器的 CPU、连接池、后端数据库等资源，使正常用户请求无法得到响应。

相比洪流式攻击，GET 攻击流量小、隐蔽性强，更难通过流量特征识别。

### 攻击特征

- 同一（组）来源 IP 的高频 GET 请求，URL 集中于少数高开销接口。
- Referer、User-Agent、Cookie 等字段缺失、固定或呈规律性变化。
- 会话行为异常：从不加载页面关联的静态资源（CSS/JS/图片），无鼠标轨迹等交互行为（网页埋点数据缺失）。

### 防御思路

- **速率限制**：基于 IP/会话设置请求频率阈值，超限返回 429 或进入人机验证。
- **人机识别**：部署 JS 挑战、验证码、行为指纹等手段区分脚本流量与真实用户。
- **资源保护**：对高开销接口单独限流、增加缓存层（CDN/Redis），避免每次请求都落到数据库。
- **访问日志分析**：统计 URL、IP、Session 维度的请求分布，动态封禁异常来源。
